> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Implement and independently review each task before starting the next; finish with whole-branch review. Track steps using checkboxes.

**Goal:** Add login, independent persistent sessions and authenticated current-user lookup as the next focused PR.

**Architecture:** Extend `auth.Usecase` with login and user lookup. Consumer-owned ports isolate password verification, session persistence, transactions, signing and time. PostgreSQL adapters share the transaction supplied by the use case; application wiring supplies concrete adapters and one shared auth IP limiter.

**Tech Stack:** Existing Go/chi/pgx/Goose/caarlos0-env/testify/mockery/Testcontainers; Ed25519 from the standard library; pin `github.com/golang-jwt/jwt/v5` v5.3.1 when implementing, check upstream advisories before installation.

**Spec:** `docs/superpowers/specs/2026-11-10-user-auth-design.md` (approved). No new product decisions or changes to the product-wide design.

## Global Constraints

- Signup remains unchanged. This PR adds `POST /v1/auth/login` and `GET /v1/users/me`; refresh/logout endpoints follow in their own PR.
- Login returns `access_token`, `token_type: Bearer`, `expires_in: 900`, `refresh_token`. It must already persist the initial refresh hash and session, even though rotation is the following PR. Keep partial auth off public deployment until the flow is complete.
- Access JWT: Ed25519/EdDSA, 15 minutes; required UUID `sub`, `sid`, `jti`, `iss=machine-whisperer`, `aud=machine-whisperer-api`, `iat`, `exp`; 30 seconds skew. Reject unknown `kid`, other algorithms, bad signatures, absent/invalid claims and future-issued tokens beyond skew. Never derive a key from token-supplied paths or URLs.
- Refresh secret: 32 cryptographically random bytes, base64url without padding; persist SHA-256 only. Session lifetime is fixed at 30 days. Each login creates a different session.
- Preserve email canonicalization and exact Unicode password rules. Unknown user and wrong password receive identical `401 authentication_failed` responses; unknown user performs one dummy Argon2id verification with existing parameters.
- Errors retain the existing JSON envelope; invalid requests `400`, auth failures `401`, limits `429`, unexpected failures `500`. No secrets, driver errors or cryptographic causes in responses or logs. Token endpoint responses use `Cache-Control: no-store`.
- Reuse strict 8 KiB decoding including raw UTF-8 and surrogate validation. Device keys cannot authenticate user endpoints.
- One shared 30/minute/IP budget across signup/login (refresh joins later); five failed login attempts per canonical email/minute. Bound state, trust only configured proxy peers, and run IP limiting before expensive work.
- Test HTTP with httptest.NewServer and a real client, storage with PostgreSQL Testcontainers in `tests/integration`, clock-sensitive rules with injected time. Use mockery for any mocks. Keep test source Unicode escaped as agreed in review.

## Review Focus

1. JWTs with a valid signature but wrong algorithm/key/issuer/audience, missing claims or future issuance never authenticate.
2. Unknown email, wrong password and concurrent failures cannot bypass generic errors, dummy verification or email limits.
3. Signing, randomness, inserts, context cancellation or commit failure never return tokens for a partially stored session.
4. Strict-decoder reuse, shared IP quotas and trusted-proxy parsing preserve every signup regression.
5. Key rotation and stateless access validation preserve logout semantics: session revocation must not immediately invalidate existing access JWTs.

## Task 2: Login orchestration and bounded email failure limits

**Files:** Create `internal/usecase/auth/{login,me}.go`, `internal/infrastructure/auth/attempts/limiter.go` and tests; extend ports/user repository; create `tests/integration/login_test.go`.

**Interfaces:** Extend consumer user repository with `FindCredentialsByEmail(ctx,email string) (user.User,string,error)` and `FindByID(ctx,id string) (user.User,error)` with a domain not-found sentinel. Extend password port with `Verify(ctx,password,hash string) (bool,error)` (regenerate mockery mocks). Add `Login(ctx,email,password string) (TokenPair,error)` and `Me(ctx,userID string) (user.User,error)` to `auth.Usecase`; `TokenPair{AccessToken,RefreshToken string; ExpiresIn int}` contains secrets only for direct transport return. Wire dependencies explicitly in constructor/option struct; update signup consumers without changing signup behavior.

The use case consumes an email-attempt port `Begin(ctx,email string) (finish func(failed bool), retryAfter time.Duration, err error)`. The bounded single-instance adapter atomically reserves in-flight verification slots; failed+in-flight attempts cannot exceed five in a minute. Complete reservations exactly once: unknown/wrong credentials count as failures, success/internal failure releases its reservation. Old-window completions must not mutate a new window; test generation/window identity. Default capacity 10,000; at capacity reject new email identities without evicting active limits. Keep this out of domain and concrete adapter imports out of use case.
