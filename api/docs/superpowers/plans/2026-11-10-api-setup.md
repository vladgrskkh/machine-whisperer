# API Initial Setup Implementation Plan

> Module layout superseded: the API is a separate module under `api/`.

> **For agentic workers:** Use superpowers:executing-plans to implement this
> plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Create a buildable, runnable API skeleton and repository-wide checks.

**Architecture:** One root Go module contains an API entry point. Its HTTP
server has no product routes and shuts down on termination signals. A root
Makefile runs checks for the module.

**Tech stack:** Go, chi, slog, testify and golangci-lint.

**Spec:** `api/docs/superpowers/specs/2026-11-10-api-setup-design.md`.

## Global constraints

- Follow `AGENTS.md`; preserve the project design and use real HTTP transport
  for handler tests.
- No telemetry, authentication, detection, database or analytics implementation.
- Use the GitHub repository path for the module. Pin tool and dependency versions.

## Review focus

- Unknown route: return HTTP 404, not an accidental success.
- Listen failure: return an error to the process and exit unsuccessfully.
- Shutdown: stop accepting connections and exit on cancellation.
- Slow request headers: configure a finite read-header timeout.
- Linter compatibility: validate the golden config against the pinned version.

## Task 1: API skeleton and tooling

**Files:** Create `go.mod`, `go.sum`, `services/api/cmd/api/main.go`,
`services/api/cmd/api/main_test.go`, `.golangci.yml`, `.gitignore`, `Makefile`
and `README.md`.

**Interfaces:** `run(ctx context.Context, address string) error` runs the API
until cancellation or a listen failure. `newHandler() http.Handler` returns a
chi router with no product routes.

- [ ] Initialize the root module `github.com/vladgrskkh/iot-idea`, add chi and
  testify, and pin compatible dependencies.
- [ ] Write a real-transport `httptest.NewServer(newHandler())` test asserting
  an unknown route returns 404. Run it and confirm it fails because the handler
  is absent.
- [ ] Implement `newHandler` with chi; run the test and confirm it passes.
- [ ] Add a test that binds a local address, invokes `run` on the same address
  and asserts a non-nil error. Run it and confirm it fails before implementing
  `run`.
- [ ] Implement `run` with an HTTP server, a finite read-header timeout,
  cancellation-driven graceful shutdown, and propagated listener errors. Use
  `slog` in `main` and an environment-configurable address. Verify the test.
- [ ] Add a cancellation test with a real listener and HTTP client, confirming
  the server exits cleanly. If the test fails, correct lifecycle handling and
  rerun it. Verify no product routes are registered.
- [ ] Add the golden golangci-lint config for v2.12.2 from upstream revision

- [ ] Run build, the complete test suite and lint; record any blocked checks.
