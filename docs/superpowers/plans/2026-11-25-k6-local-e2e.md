# Local k6 E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the demo seed and k6 telemetry scenarios against a disposable real Compose stack in CI.

**Architecture:** Start an isolated full deployment, run the existing seed inside a temporary Python/Docker CLI container attached to the Compose edge network, and run k6 on that same network over verified HTTPS. Keep the k6 archive command as a fast load check and remove the fake Node VM behavior suite.

**Tech Stack:** Docker Compose, Bash, Python 3, Nginx, PostgreSQL, ClickHouse, Go API/Analytics, k6 `grafana/k6:1.8.2`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-25-k6-local-e2e-design.md`

## Global Constraints

- Keep production seed defaults unchanged: `.env.server`, Compose `DOMAIN`, public HTTPS origin, and fixture path `deploy/secrets/k6-demo-fixtures.json`.
- Keep generated owner passwords, device keys, claim codes, and fixture contents out of stdout, stderr, Docker arguments, CI logs, and committed files.
- Telemetry must flow through the API and outbox; never write telemetry directly to PostgreSQL or ClickHouse.
- Use an isolated random Compose project and clean up containers, networks, volumes, local images, and temporary files on success and failure.
- Keep `SCENARIO` values `healthy`, `alert`, `recovery`, `unknown`, and `all`; keep `SIMULATIONS` limited to `1`, `2`, or `3`.
- Preserve deployed-host `run-k6-demo.sh` behavior when the new local E2E inputs are unset.
- Use pinned public images already used by the deployment, `grafana/k6:1.8.2` for k6, and `python:3.14.10-alpine3.24` for the disposable seed runner.

## Review Focus

1. A failed E2E run must still remove the random Compose project's containers, networks, volumes, local images, and temporary fixture files; Task 1's cleanup assertions and final E2E verification cover this.
2. Local E2E credentials must never appear in process arguments or logs; Task 1 mounts config and fixture files and Task 2's CI log behavior review covers this.
3. The k6 container must resolve `k6-e2e.test` and trust only the disposable certificate; Task 1 exercises this through a real HTTPS run.
4. Production runner behavior must stay unchanged when `K6_DOCKER_NETWORK` and `K6_CA_FILE` are unset; Task 1 runs the existing deployed-host contract path before removal of the fake behavior suite and Task 3 verifies the final runner.
5. The `alert` and `recovery` immediate reruns must work against real detector state; Task 1 includes both reruns after the initial `all` run.

### Task 1: Run seed and k6 against a disposable Compose stack

**Files:**
- Create: `deploy/scripts/test-k6-demo-e2e.sh`
- Create: `deploy/k6-e2e-runner.Dockerfile`
- Modify: `deploy/scripts/run-k6-demo.sh`

**Interfaces:**
- Consumes: existing `deploy/scripts/prepare-secrets.sh`, `deploy/scripts/seed-demo-data.py`, `deploy/compose.yaml`, and `deploy/k6/telemetry-scenarios.js`.
- Produces: `deploy/scripts/test-k6-demo-e2e.sh`, which starts an isolated stack, seeds `SIMULATIONS=1`, runs `SCENARIO=all`, then reruns `SCENARIO=alert` and `SCENARIO=recovery`.
- Produces runner inputs: optional `K6_DOCKER_NETWORK` (Docker network name) and `K6_CA_FILE` (host path to a PEM file). When set, `run-k6-demo.sh` joins that network and mounts the PEM as `/demo-ca.pem` with `SSL_CERT_FILE=/demo-ca.pem`.

- [ ] **Step 1: Write the failing E2E script and runner image**

Create `deploy/k6-e2e-runner.Dockerfile` from `python:3.14.10-alpine3.24` with Docker CLI and Compose plugin installed; set no entrypoint that would hide the seed command. Create an executable Bash E2E script that:
- Creates a random `mw-k6-e2e-<hex>` Compose project and temporary work directory.
- Generates deployment secrets with `prepare-secrets.sh` and a disposable self-signed certificate for `k6-e2e.test`.
- Writes a Compose override that removes host port publication and gives Nginx the `k6-e2e.test` alias on the edge network.
- Builds and starts the full stack with `--wait`.
- Builds a disposable `mw-k6-e2e-runner` image from `deploy/k6-e2e-runner.Dockerfile`.
- Runs the existing seed from a read-only repo mount inside that container, with the Docker socket, temporary env file, writable fixture directory, generated CA, `COMPOSE_PROJECT_NAME`, and edge network attached.
- Runs `run-k6-demo.sh` with `FIXTURES_FILE`, `K6_DOCKER_NETWORK`, `K6_CA_FILE`, `SCENARIO=all`, and `SIMULATIONS=1`, then reruns `alert` and `recovery`.
- Traps cleanup and removes the Compose project, local API/Analytics/runner images, temporary files, and fixture directory.
